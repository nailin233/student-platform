# 客户演示流程 · 学员管理平台 Demo V1.0

> 本文档是演示时的**操作手册**。按顺序走一遍，全程约 10 分钟。
> 演示前请先完成「演示前准备」清单，确保环境就绪。

---

## 一、演示前准备（演示前 10 分钟做）

### 1. 确认服务在线

```bash
# 数据库（Docker）
docker ps | grep mysql
# 应看到 student-platform-demo-mysql-1 处于 Up 状态

# 后端
curl http://localhost:8000/api/health
# 应返回 {"status":"ok","message":"student platform backend is running"}
```

### 2. 启动前端

```bash
cd frontend
npm run dev
```

浏览器打开 **http://localhost:5173**，确认能看到登录页。

### 3. 重置演示数据（重要）

如果上一次演示时改动过数据，先重置回标准演示数据：

```bash
cd backend
./.venv/Scripts/python.exe ../database/seed_demo.py
```

应输出「学员 6 名，缴费流水 6 条，待收金额 ¥2120.00」。

### 4. 浏览器准备

- 只留**一个标签页**，关闭无关标签和书签栏（投影时更干净）
- 浏览器缩放调至 **100%**，窗口最大化
- 提前登录一次，避免演示开始时卡在登录页

## 二、演示主线（按顺序操作）

### 第 1 站 · 登录（30 秒）

**操作**：在登录页输入管理员账号，点击登录。

**预期**：进入「工作台」。

**话术要点**：
> "这是机构管理端的登录入口。演示版本用的是固定管理员账号，正式版可以按老师、前台等角色分配权限。"

**顺带展示校验**：故意留空点登录 → 提示「请填写用户名/密码」。说明"系统有基本的输入校验，不会让人误操作"。

---

### 第 2 站 · 工作台（1 分钟）

**操作**：指着三个统计卡片讲。

**预期**：学员 6 人、课程 3 门、老师 3 位、待收金额 ¥2120.00。

**话术要点**：
> "管理员一进来看的就是这四个数——在读多少学员、开了多少门课、多少位老师、还有多少学费没收到。
> 待收金额是自动算出来的：每个学员的应缴减已缴，加总得出。不用人工统计表。"

**这是拉高印象分的关键页**：把"待收 ¥2120"和后面「缴费管理」串起来讲。

---

### 第 3 站 · 学员管理（3 分钟，核心）

**操作 1 · 浏览列表**

指表格，说明列：姓名、性别、年龄、电话、课程、老师、上课时间、应缴、已缴、状态。

**话术要点**：
> "所有报名的学员都在这张表里。您看这几列——课程和老师是关联出来的，不是手打的，
> 所以改课程名字，这里会自动跟着变，不会出现前后对不上的情况。"

**操作 2 · 搜索**

在搜索框输入 `谭` 或手机号 `18172203647`，点「查询」。

**预期**：筛出谭贵锋。

**话术要点**：
> "家长打电话来报手机号，您直接搜手机号就能找到人，不用翻表格。"

**操作 3 · 查看详情**

点任一学员的「详情」。

**预期**：弹窗展示 16 个字段，包括紧急联系人、紧急联系电话、缴费时间、缴费方式、学制、备注。

**话术要点**：
> "点开每个人，完整资料都在这——包括紧急联系人，万一学员在上课期间有情况能第一时间联系到家属。"

**操作 4 · 新增学员（重点演示）**

点「新增学员」，填一份完整资料：

| 字段 | 填写内容 |
|---|---|
| 姓名 | 张小明 |
| 性别 | 男 |
| 年龄 | 24 |
| 联系电话 | 13800008888 |
| 紧急联系人 | 张母 |
| 紧急联系电话 | 13800008899 |
| 所选课程 | 摄影班 |
| 任课老师 | 李老师 |
| 应缴金额 | 980 |
| 学制 | 8周 |

点保存。

**预期**：弹窗关闭，提示「学员已添加」，列表顶部出现张小明。

**话术要点**：
> "前台收到一个报名，三四十秒就能录完。录完立刻出现在列表里。"

**操作 5 · 删除（可选，用于说明安全性）**

点张小明的「删除」。

**预期**：弹二次确认框，**文案里带学员姓名**。

**话术要点**：
> "删除这种不可逆操作，系统会弹确认框，并且把要删的人名写清楚，
> 防止手滑删错人。这也是为了照顾不熟悉电脑的同事。"

### 第 4 站 · 课程管理（1.5 分钟）

**操作 1 · 看列表**

三张课程卡片/表格行：书法班 ¥1280、摄影班 ¥980、声乐班 ¥1680。

**操作 2 · 新增一门课**

点「新增课程」，填：`国画班` / `中国画基础` / `10周` / `1180` / `周五 19:00-21:00`。

**预期**：新增成功。

**操作 3 · 回到学员页**

去学员新增弹窗，展开「所选课程」下拉。

**预期**：国画班出现在选项里。

**话术要点**：
> "新增课程后，学员报名时马上就能选到——课程和报名是打通的，不用另外维护一份名单。"

> **演示完记得删掉国画班**，保持数据干净。

---

### 第 5 站 · 老师管理（1 分钟）

**操作**：同课程管理，展示老师列表（王老师-书法、李老师-摄影、陈老师-声乐），每位有联系电话和专业方向。

**话术要点**：
> "老师的专业方向和联系方式都在这。学员分配老师时从下拉里选，避免名字写错。"

---

### 第 6 站 · Excel 导出（1.5 分钟，让客户拿到实物）

**操作**：点「导出」下拉 → 依次选「导出学员信息」「导出缴费信息」。

**预期**：两个 .xlsx 文件下载。

**打开给客户看**：

- **学员信息**：15 列，6 行数据，中文表头，字段完整
- **缴费信息**：6 条缴费流水，按时间倒序，含缴费方式与备注

**话术要点**：
> "要交给会计、或者要做月度报表，一键导出成 Excel，直接打开就能用。
> 这是真实的文件，不是截图。"

**建议**：把导出的文件当场发给客户（微信/邮件），是最有说服力的交付感。

---

### 第 7 站 · 微信小程序报名（2 分钟，压轴）

**操作**：切到微信开发者工具（或手机扫码预览）。

**演示路径**：

1. **课程 Tab**：展示课程列表，价格显示 `¥1680.00`（两位小数）
2. **点某门课 → 报名**：填姓名、性别（选择器）、年龄、手机号
3. **故意填错手机号**（如 `123`）→ 提示校验不通过
4. **改正后提交** → 成功页显示「报名已提交」并回显姓名
5. **老师 Tab**：展示师资团队，可点击拨号
6. **我的 Tab**：看到刚才的报名记录

**话术要点**：
> "家长在微信里就能看课程、直接报名，不用专门跑一趟。
> 报名信息进了系统，后台立刻能看到——这就是前面说的'学员端口'。"

**如果客户问"能不能在线支付"**：
> "Demo 版本没接支付，因为正式收款需要企业资质和微信支付商户号。
> 这块在正式版里加上，报名后可以直接付款。"

## 四、可能被问到的问题（提前准备答案）

| 客户问 | 建议回答 |
|---|---|
| 能多人同时用吗？ | 能。系统是 B/S 架构，装了服务器的局域网内多台电脑都能访问 |
| 数据会丢吗？ | 数据存在 MySQL 数据库里，会定期备份。演示环境是 Docker 部署，正式版会单独规划备份策略 |
| 能不能按班级看学员？ | 目前支持按姓名/手机号搜索、按课程关联查看。按班级分组可以加，属于后续迭代 |
| 能不能发短信通知？ | Demo 未接短信服务。接入短信需要另外采购服务，可以后续加 |
| 能导出成 PDF 吗？ | 目前导出 Excel。PDF 格式如果需要可以加 |
| 手机能管后台吗？ | 管理后台目前是电脑端（表格操作在电脑上更方便）。手机端做的是家长报名入口 |
| 这个要多少钱？ | **不要在现场报价**。回答"正式版会根据功能范围出方案，我整理好发您" |

## 五、演示禁忌

- ❌ **不要现场改数据库**、不要演示删除课程/老师（可能影响关联数据）
- ❌ **不要开多个浏览器标签**，容易点到旧页面导致状态混乱
- ❌ **不要在演示中途改代码**（前端 dev 服务会热更新，页面会闪）
- ✅ 演示前**务必重置演示数据**，避免上次演示的残留数据（比如测试学员"张小明"）出现在客户面前
- ✅ 提前把演示数据导出的 Excel 存一份在桌面，万一网络/服务出问题可以拿文件兜底

## 六、出问题时的应急处理

| 现象 | 处理 |
|---|---|
| 前端白屏 | 检查 `npm run dev` 是否还在跑；刷新页面 |
| 列表空 / 提示连接失败 | 检查后端：`curl http://localhost:8000/api/health`；未响应则重启后端 |
| 数据被改乱 | 停演示，执行 `python database/seed_demo.py` 重置，然后重新登录 |
| 导出没反应 | 检查浏览器是否拦截了下载；换 Chrome/Edge |
| 小程序连不上 | 确认后端在跑，且 `miniprogram/config.js` 里 `ENV` 与实际环境匹配 |
